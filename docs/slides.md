# スライド形式

mdz-guiのスライドを保存するときのファイル形式です。MDZip仕様にはない、mdz-gui独自の拡張(`mode: "slides"`)です。

- ほかのMDZipアプリでは開けない場合があります。
- 中身はZIPなので、本文や画像を取り出すことはできます。

## 基本の考え方

- 1枚のスライド = 1つのMarkdownファイル
- 並び順と設定は、本文とは別の`slides.json`に保存する
- 画像は別ファイルとして保存し、本文から相対パスで参照する(Base64埋め込みはしない)

## MDZ内のファイル

| パス | 内容 |
| --- | --- |
| `manifest.json` | `mode`は`slides`。`entryPoint`は先頭スライドのMarkdown。未知の項目は保持する |
| `slides.json` | 資料全体の設定と、スライドの並び |
| `slides/slide-001.md` など | 各スライドの本文。本文中の`---`では改ページしない |
| `images/` など | 画像。保存先はアプリの画像設定に従う |

## slides.json

### 資料全体の設定

| 項目 | 内容 | 新規作成時の値 |
| --- | --- | --- |
| `version` | 保存形式のバージョン。現在は`1`。知らない値なら読み込みを拒否する | `1` |
| `title` | 資料タイトル | ― |
| `theme` | `light` / `dark`。アプリのテーマとは別 | ― |
| `marginColor` | 余白の色(`#RRGGBB`) | 白 |
| `aspect` | `16:9` / `4:3` | `16:9` |
| `fontFamily` | `system` / `gothic` / `mincho` / `monospace` | `system` |
| `bodyFontSize` | 本文の文字サイズ(12〜64) | `20` |
| `h1FontSize`〜`h5FontSize` | 見出しの文字サイズ(14〜96)。H1 > H2 > H3 > H4 > H5 でなければならない | 42 / 28 / 26 / 24 / 22 |
| `slides` | スライドの配列(1〜500個)。この順に表示する | ― |

`version`は保存形式の番号で、アプリのバージョンとは関係ありません。

### スライドごとの設定(`slides`の要素)

| 項目 | 内容 |
| --- | --- |
| `id` | 文書内で一意なID。並べ替えても変わらない |
| `file` | 本文ファイルの相対パス。重複や、文書の外を指すパスは拒否する |
| `title` | サムネイル一覧に出す名前。本文の見出しとは別 |
| `layout` | `standard` / `cover` / `image` / `columns` |
| `fontSize` | 古い形式との互換用(18〜64)。`bodyFontSize`がないときだけ使う |
| `background` | 背景色。空欄か`#RRGGBB` |
| `notes` | 発表者ノート。発表画面には出ないが、MDZを渡せば読まれる |

### 読み込みと保存のルール

- 表示順と開始ページは`slides.json`を正とします。保存時にmanifestの`entryPoint`も先頭スライドに合わせます。
- スライドを削除しても、一覧から外すだけです。本文と画像は「元に戻す」と既存の参照のために残します。
- 構成の操作履歴はメモリ上にだけあり、文書を開き直すと消えます。
- `slides.json`の未知の項目が、編集・保存後も残ることは現時点では保証しません。

## 通常のMDZとの相互変換

編集モードで、通常のMDZとスライドを相互に変換できます。mdBookは対象外です。

### 通常のMDZ → スライド

1. ページを現在の並び順で読みます。
2. コードブロックの外にある`---`だけの行で、1枚ずつに分けます。
3. 分けたMarkdownは、元のファイルと同じフォルダーに置きます(画像やリンクの相対パスが変わらないようにするため)。
4. 各スライドの先頭に、元に戻すための情報をコメントで書き込みます。プレビューには表示されません。

```html
<!-- mdz-gui:normal-source {"version":1,"file":"docs/guide.md","page":2,"part":1,"parts":3,"mode":"document","entry":false} -->
```

| 項目 | 意味 |
| --- | --- |
| `file` | 元のMarkdownのパス |
| `page` | 通常のMDZ全体での、何番目のページだったか |
| `part` / `parts` | そのファイルを何枚に分けたうちの何枚目か |
| `mode` / `entry` | 通常のMDZへ戻すときに使う情報 |

このコメントは、ファイルの先頭20行以内にあるときだけ認識します。パスが文書の外を指すものや、知らない形式のものは無視します。

### スライド → 通常のMDZ

現在の`slides.json`の並び順をもとに組み立てます。

| スライドの状態 | 戻り方 |
| --- | --- |
| 同じ元ファイルから来た複数のスライド | `---`を挟んで1つに結合し、元のファイル名に戻す。順番は今のスライド順 |
| 変換後に追加したスライド | 新しいページになる |
| 複製したスライド | 元ファイルの情報を外し、新しいページになる |
| 一覧から削除したスライド | 戻さない(作業データに残っていても) |
| 元ファイルの情報が1枚もない資料 | 全スライドを`---`でつないだ1ページにする |

同じ元ファイルのスライドの間に別のスライドを挟んだ場合、1つのファイルの途中に別ファイルは置けないため、その元ファイルは最初に出てきた位置にまとめます。

元の開始ページが残っていれば`entryPoint`も元に戻します。削除されていれば、先頭のページを開始ページにします。

## 表示のしくみ

- Markdownの変換にはGoldmarkを使い、生のHTMLは無効にしています。
- 画像は文書内の相対パスだけ表示します。
- 表示エンジンはreveal.js 5.2.1です。npmで版を固定し、JavaScript・CSS・MITライセンスをビルド時にEXEに同梱します。資料には含めません。
- 編集プレビュー・サムネイル・発表で、同じCSSと変換処理を使います。

### キャンバスの大きさ

| 縦横比 | 大きさ |
| --- | --- |
| 16:9 | 960×540 |
| 4:3 | 960×720 |

ウィンドウの大きさに合わせて全体を拡大・縮小します。

### はみ出しの扱い

- 自動の改ページや文字の縮小はせず、はみ出したことだけを知らせます。
- 編集プレビューだけは`overflow: visible`にして、はみ出た部分を黒い枠の外に表示します。
- 要素枠の表示は、編集中の確認用です。`slides.json`には保存しません。

### 区切りの扱い

| 区切り | 使われる場面 | 規則 |
| --- | --- | --- |
| `<!-- column -->` | 左右2列レイアウト | 前後を空行で挟む。最初の区切りの前が左、後が右。コードブロック内は無視 |
| `---` | ページ分割、Markdown取り込み | コードブロックの外にある、`---`だけの行 |

YAMLやMarpを完全に解釈するわけではありません。

### セキュリティ

| 表示先 | 制限 |
| --- | --- |
| サムネイル | スクリプトを禁止したiframe |
| スライド本体 | アプリ同梱のスクリプトだけを許可するCSP付きiframe |

文書に含まれるスクリプトやCSSは、どこでも読み込みません。

## 発表のしくみ

- Windows版はWailsのウィンドウ全画面化を使います。発表のために全画面にした場合だけ、終了時に元へ戻します。
- ブラウザーで確認するときは、Fullscreen APIを使います。
- 操作方法はREADMEの「スライド」の章を見てください。

## 2画面モードのしくみ

- 投影用ウィンドウは、同じEXEを別プロセスとして起動したものです。
- 発表者側が開始時点の描画結果と画像を持ち、ループバック(127.0.0.1)のHTTP接続で、表示ページと全画面の状態を同期します。接続はランダムな鍵で保護します。
- 投影側へは、ノート・Markdown・`slides.json`を送りません。
- 発表者側が終了したり資料を切り替えたりすると、投影プロセスとサーバーを終了します。投影側も接続が切れたことを検出して終了します。

## サムネイルの更新

- 構成や設定が変わらないページ選択では、サムネイルを作り直さず、選択状態だけを変えます。
- 画像の更新や画面幅の変更で描画し直すときも、スクロール位置は保ちます。
