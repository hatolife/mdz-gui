# 開発テスト

テストは大きく2種類あります。

| 種類 | 実行方法 | 必要なもの |
| --- | --- | --- |
| Goの単体テスト | `go test ./...` | Go |
| 画面の結合テスト | テスト用ブリッジ + Playwright | Go、Node.js 22.18以降、Chromium |

どちらもWindows実機での確認を完全には置き換えません。最後に[Windows実機で手で確認すること](#windows実機で手で確認すること)を見てください。

## 環境変数

| 変数 | 意味 | 未設定のとき |
| --- | --- | --- |
| `MDZ_NVIM_TEST` | Neovimの実行ファイル | 実Neovimを使うテストをスキップ |
| `MDZ_MDBOOK_TEST` | mdBookの実行ファイル | 実mdBookを使うテストをスキップ |
| `MDZ_BROWSER_BRIDGE` | ブリッジの接続URLを書き出すファイル | ブリッジを起動しない |
| `MDZ_BRIDGE_URL` | 画面テスト側が読む接続URLのファイル(上と同じファイル) | ― |
| `MDZ_CHROMIUM` | 使うChromiumの実行ファイル | Playwright標準のChromium |

## Goの単体テスト

```sh
go test ./... -timeout 120s
```

主に次のことを確認しています。

### MDZと作業データ

- 開始ページの判定
- 不正なパス、暗号化されたZIP、サイズ上限の拒否
- 本文・画像・メタデータの保存と再読込
- 作業フォルダーへの展開。Windowsの予約名、大文字小文字の衝突、シンボリックリンクの拒否
- 世代バックアップと世代数の制限
- 保存先がほかのアプリに変更されたことの検出
- 異常終了を想定した復旧
- 画像リンクを元に戻した後も画像が残ること

### Neovim(`MDZ_NVIM_TEST`を設定したとき)

- 日本語入力
- ページ切り替え後の元に戻す / やり直す
- 画像リンクの元に戻す / やり直す
- Undo保持数の変更
- `:w`の通知

Neovimの探し方(Windows優先、既定のWSLへの切り替え、明示したパスの優先、WSLがない・設定がない場合)と起動引数は、Neovimがなくても単体テストします。

### mdBook

- 目次の追加・名前変更・階層移動・元に戻す / やり直す
- 本文が消えないこと、外部変更の検出
- `book.toml`の検証と保存
- Neovimと同時に編集したとき
- wingetのパス(USERPROFILE以下)

`MDZ_MDBOOK_TEST`を設定すると、実際の`mdbook serve`の起動・終了と、生成HTMLがMDZに混ざらないことも確認します。基準の版はmdBook 0.5.4です。wingetによる実際のインストールは自動テストしていません。

### スライド

- 並び順と開始ページ
- 複製したときの画像参照
- 構成の元に戻す / やり直す
- 設定の読み書き、不正な設定や古いrevisionの拒否
- 取り込み時にコードブロックを壊さないこと
- 危険なHTMLの除去
- ZIPの保存と再読込、異常終了からの復旧
- 2画面モードの投影サーバー: 接続鍵、配信する画像の範囲、ノートと本文ファイルを渡さないこと

## 画面の結合テスト

実際のGoバックエンドをHTTPで公開し、ブラウザーからアプリの画面を操作するテストです。

### しくみ

`bridge_test.go`は、`MDZ_BROWSER_BRIDGE`を設定したときだけ、localhostにテスト用のHTTPブリッジを起動します。通常のアプリや配布EXEには含まれません。

| エンドポイント | 役割 |
| --- | --- |
| `/rpc/<メソッド名>` | 引数をJSON配列でPOSTする。Wailsのバインドの代わり |
| `/events` | ポーリングで読む。Wailsのイベントの代わり |
| `/test-info` | テスト用の保存先(`document.mdz`)の場所を返す |

保存ダイアログは、テスト用の`document.mdz`に置き換えています。

### 手順

**1. 画面をビルドします。**

```sh
npm run build --prefix frontend
```

**2. ブリッジを起動します(ターミナル1)。**

```sh
export MDZ_NVIM_TEST=/path/to/nvim
export MDZ_BROWSER_BRIDGE=/tmp/mdz-bridge-url
go test -run '^TestBrowserBridge$' -timeout 20m -v
```

mdBookも試すなら`MDZ_MDBOOK_TEST`も設定します。

**3. 画面テストを実行します(ターミナル2)。**

```sh
export MDZ_BRIDGE_URL=/tmp/mdz-bridge-url
npm run test:ui --prefix frontend
```

Chromiumは`npx playwright install chromium`で入れるか、`MDZ_CHROMIUM`で既存のものを指定します。テストが成功すると、ブリッジも自動で終了します。スクリーンショットはOSの一時フォルダーに出力します。

別のテストを実行するときは、ブリッジを起動し直してください。

### テストの種類

| コマンド | スクリプト | 主に確認すること |
| --- | --- | --- |
| `npm run test:ui` | `frontend/tests/integration.ts` | 基本操作とmdBook |
| `npm run test:slides` | スライド用 | スライドの作成から発表まで |
| `npm run test:layout` | 画面配置用 | 左の操作列とテーマ |

#### test:ui

- 内蔵エディターと実Neovimの両方で、入力・画像貼り付け・元に戻す / やり直す・設定変更・`:w`
- 5秒間隔の自動保存、2世代のバックアップ
- ZIPの中の本文と画像
- 開始画面、表示から編集への切り替え、ツリーの折りたたみ、テーマ
- mdBookの新規作成・目次の編集・プレビュー、プレビューで目次が二重にならないこと
- 設定画面の読み取り専用の切り替え、ページとプレビューの連動、プレビュー内での`Ctrl+S`

#### test:slides

- 作成・編集・画像の貼り付け・左右2列・文字の設定
- ページ分割・はみ出し警告・枠外の表示・要素枠の表示
- 並べ替えと元に戻す / やり直す・取り込み・保存と再読込
- 発表と一覧表示・通常の文書への切り替え
- 全画面の表示範囲、発表中に移動ボタンが出ないこと
- 矢印・Enter・左右クリック・ホイールの連続入力、先頭と末尾で止まること、右クリックでの終了
- 2画面モード: 同期・全画面の指示・タイマー・ノートを渡さないこと・Escでの終了
- サムネイルのDOMとスクロール位置の保持、余白のクリックと色、右クリックメニュー
- 通常の文書: 拡張子の省略、フォルダーをまたぐ並べ替え、保存・再読込・復旧、相対リンクと未知のmanifest項目の保持
- 依存アプリが見つからないときの表示

Wailsの全画面APIは、呼び出しと状態の復元をモックで確認しています。

#### test:layout

- 起動画面・mdBook・同梱ヘルプ・スライドの表示
- 3色のアクセントとライト / ダーク
- 800×520のウィンドウでのボタン配置
- サイドバーの開閉と幅の変更
- ウィンドウ操作の呼び出し

このテストでは、mdBookの本文は通常のMarkdownプレビューで表示します。

## Windows実機で手で確認すること

ブラウザーでは再現できないため、必要に応じてWindowsで手で確認してください。

| 分野 | 確認すること |
| --- | --- |
| WebView2・IME | 実際のWebView2での表示、各IMEでの日本語入力 |
| ウィンドウ | タイトルバーなしでのドラッグ移動・端のリサイズ・最小化・最大化と復元・未保存時の終了確認 |
| スライド | 全画面でタイトルバーが消えること、2画面モードの別プロセス起動、実際の複数モニターへの移動 |
| WSL | 既定ユーザーのシェル設定で追加したPATHの検出。空白や日本語を含むファイルの編集・保存・ページ移動・元に戻す。指定したinitファイルの読み込み |
| mdBook | mdBook 0.5.4での実行 |
